# 每个人的 Duet 如何接起一条业务闭环

## 视频定位

面向第一次接触这套设计的同事和业务负责人。看完后，观众应能说清员工怎样委托自己的 Duet、工作怎样跨岗位流转，以及 Agent Loop、Message Center 和 LoopLab 在什么时候参与。

主故事采用一项假设的监管变化。客户需要看见自己的申请处理状态，公司内部报表也需要导出该状态。Nora 负责市场研究，Maya 负责产品，Alex 负责开发，Sam 负责评审与测试。鲍勃的报表委托是开场的日常小例子。

全片预计 8–10 分钟。每个场景由连续的小动作组成，名称和架构随着任务推进逐步出现。画面保持白色、石墨色和少量红色，产品控件使用英文，人物消息和讲解使用中文。以下时间是剪辑参考，旁白录制后按实际节奏调整。

## 01 每个人先交出一部分工作

### 观众理解

AI Native 从个人委托开始。工作形成闭环，需要交付物能被下一位负责人直接使用，并且有明确的完成条件。

### 画面推进

约 30 秒。先出现一位员工及其 Duet，依次移交「收集资料」「整理报表」「跟进进展」三个小任务。镜头展开，出现市场、产品、开发、测试四位员工，每人身边都有自己的 Duet。沿着资料、需求、代码、验收结果画出一条路径，终点暂时保持空白。每 5–7 秒增加一个角色或交付物。

### 旁白

一家公司的工作，由很多人的职责接在一起。每个人都可以先把一部分事情交给自己的 AI，比如收集资料、做报表，或者持续跟进一项任务。这里，每位员工的个人 AI 叫作 Duet。当一个 Duet 交出的结果能被下一位负责人直接使用，这些个人委托就开始连起来。等一条业务有了明确的起点、交接和验收条件，它就可以在规则与人的判断下持续推进。这是我们理解的 AI Native。

### 转场

镜头收回到一条普通的真人消息，让观众先看清一次委托如何发生。

## 02 鲍勃要一份报表

### 观众理解

员工调用自己的 Duet。以本人身份代发来自本次任务的明确指令。

### 画面推进

约 40 秒。鲍勃在真人私聊发来「请帮我做一份本周报表，做好发给我」。员工选中消息，点击 **Ask my Duet**，原消息以引用形式进入自己的 Duet。员工输入「帮我做好这份报表，然后发给鲍勃」。依次展示整理数据、生成报表、文件就绪。最后回到原私聊，由员工本人头像发出附件，鲍勃打开报表。发送动作要在明确委托出现之后。

### 旁白

鲍勃给我发来一条消息，请我做一份报表。我选中他的消息，交给自己的 Duet，并告诉它，帮我做好这份报表，然后发给鲍勃。引用带来了原始要求，也带来了要回复的那段对话。我的 Duet 整理数据，完成报表，再调用发送工具，以我的身份把文件发回与鲍勃的私聊。这个发送动作来自我刚才的明确委托。鲍勃收到材料，就能继续他的工作。一次小任务已经跨过了一个岗位交接点。

### 转场

报表附件缩成已完成事项，镜头停在 My Duet，进入长期使用体验。

## 03 始终面对自己的 Duet

### 观众理解

Duet 有持续的身份和职责。员工用一个前台入口处理多件事情，并逐步教会它自己的做事方式。

### 画面推进

约 35 秒。固定一个 **My Duet** 入口，员工先交报表任务，再问客户问题，随后要求研究行业变化。后台三个任务分别展开，结果陆续回到同一入口。侧面短暂展示员工教给 Duet 的规则「研究结论附来源」「优先说明对当前项目的影响」。较早消息缩成摘要，最近问答保留原文。

### 旁白

Duet 会长期跟随同一位员工。你可以教它自己的职责、常用资料、工作标准和表达习惯。一天里，你可能先交代报表，再讨论客户问题，然后问起另一项研究。眼前始终是同一个 Duet，它在后台分别处理这些事情，并把结果带回来。对话持续变长时，较早内容会压缩成摘要，最近几条问答保留原文。你能接着刚才的话说，也能在之后重新找回一项持续中的工作。

### 转场

画面出现周一的日期，一条外部资讯进入公司，开始完整业务故事。

## 04 消息中心先让变化被看见

### 观众理解

Message Center 汇集可阅读的信息，也支持搜索、订阅和拉取。信息可以先沉淀，等待相关员工判断是否行动。

### 画面推进

约 40 秒。爬虫发现示例监管更新，将原文链接、发布时间、摘要和分类合成一张消息卡。卡片进入 **Message Center**，与客户反馈、行业资讯和业务通知并列。依次点亮 **Search**、**Subscribe** 和定时拉取入口。随后高亮 Nora 的研究订阅，旁边保留其他尚未启动工作的资讯卡。

### 旁白

设想周一，爬虫发现了一条监管变化，提出客户需要了解申请的处理状态。消息中心保存原文链接和发布时间，将内容整理成可阅读的摘要并分类。员工可以浏览、搜索和订阅，Duet 也可以按职责主动查找或定期拉取。消息中心让外部变化进入公司的共同信息范围。一条资讯可以先留在这里，等它与某个人手上的工作发生联系，再进入后续行动。

### 转场

从共享资讯卡切到 Nora 的个人工作视角，解释同一条消息为什么值得她关注。

## 05 Nora 决定把消息变成需求

### 观众理解

Duet 结合个人工作判断相关性，人决定是否投入。调研的产出要让产品负责人可以继续工作。

### 画面推进

约 45 秒。Nora 的 Duet 将消息与「客户申请体验」Tracking 连接，给出「当前申请页面可能需要增加状态展示」的推荐。Nora 回复「请调研影响，整理报告，并给出需求建议」。画面逐步生成三份内容，一页影响清单、带来源的研究报告、初步 story。报告重点标出客户界面和内部报表两个受影响位置，随后交给产品负责人 Maya。

### 旁白

Nora 负责市场研究。她的 Duet 知道，她正在关注客户申请体验，于是把这条变化推荐给她，并解释可能影响现有申请页面。Nora 判断值得投入，委托 Duet 调研影响，整理报告，并形成需求建议。交付物逐渐具体起来。哪些流程受影响，原文依据在哪里，客户应该看见什么，内部人员又需要导出什么。Maya 收到这些材料后，就能把研究结论继续整理成产品需求。

### 转场

研究报告打开在 Maya 的屏幕上，镜头展开为真人群聊和关联的 Agent 主题。

## 06 人在群聊里沟通 Duet 在主题里协作

### 观众理解

真人对话与 Agent 主题各自承接合适的交流。员工从真人消息调用自己的 Duet，Duet 再在主题内与其他 Duet 异步协作。

### 画面推进

约 50 秒。Nora 委托自己的 Duet 建立含 Nora、Maya、Alex、Sam 的真人群，并建立绑定主题「申请状态可见」。主题标出 **Topic owner · Nora’s Duet**。真人群中 Nora 提出需求，Maya 选中消息，点击 **Ask my Duet**。一条清晰的线只连接 Maya 和 Maya’s Duet，再进入主题。Nora’s Duet 在主题中发布报告，@ Maya’s Duet、Alex’s Duet 和 Sam’s Duet，各方异步留下需求、技术意见和测试问题。共享文件夹始终可见。

### 旁白

Nora 可以请自己的 Duet 建立一个真人群，把产品、开发和测试同事拉进来。大家在群里讨论范围和优先级。Maya 看到一条需要处理的消息，就把它交给自己的 Duet。与此同时，Nora 的 Duet 创建并管理一个绑定主题，将报告放进去，再邀请相关 Duet 留言协作。每个 Duet 带着自己主人的职责参与，按主人在群里的权限读取共享历史和文件。人直接联系自己的 Duet，Duet 之间的工作则围绕主题异步展开。

### 转场

主题里生成明确分工，日历从周一翻到周四。Nora 再次打开同一个 Duet。

## 07 跨天以后它怎样接着做

### 观众理解

短期上下文、Dream 和 Tracking 分别支持当前交流、长期认识和持续事项。Git 保存记忆版本与来源，Duet 依据证据处理更新。

### 画面推进

约 65 秒。周一的任务、期间若干无关对话、周四「申请状态那件事到哪了」依次出现。逐步展开三层信息，每次只突出一层。短期层显示摘要和最近问答。Dream 层显示每四小时增量扫描主人可见的所有群聊及其与 Duet 的对话，提取「研究报告附原文」「Nora 负责市场影响」，再展示 Git 的一条版本变化及来源链接。Tracking 层显示常驻首节点「申请状态响应」，点击后读出「启动调研 → 报告交付 → 需求明确 → 开发接手」。再展示计划日期由周五改为下周一的来源及修改记录。

### 旁白

到了周四，Nora 只要问，申请状态那件事到哪了。Duet 会用几层记忆找回工作。短期上下文保存摘要和最近问答。每四小时，Dream 从主人可见的所有群聊及其与 Duet 的对话中增量整理长期信息，Git 留下版本和来源。若周一与周四的计划有出入，Duet 能查证据，依据有效决定更新记忆。Duet 识别到持续事项后，会主动建立 Tracking 记录。首节点写下事项、目标和简述，这些元数据留在日常上下文里，帮助定位工作。详细进度按需读取，新的决定和交付继续追加节点。于是，任务可以跨过很多次对话继续推进。

### 转场

Tracking 中「开发接手」节点展开为 Alex 的代码改动，进入确定规则驱动的接力。

## 08 Agent Loop 把明确的事件交给负责人

### 观众理解

Agent Loop 是独立项目，无需 LLM。policy 使用结构化事件和结论决定下一棒，Duet 负责实际理解与执行。

### 画面推进

约 55 秒。Alex 的 Duet 根据 Maya 明确的 story 实现客户申请状态展示并创建 PR。事件卡显示 `pull_request.opened`、PR 编号及提交版本。外圈 Agent Loop 出现，一张可读 policy 依次点亮「新 PR → 评审负责人 Sam」「需要修改 → 作者 Alex」「评审通过 → 验收」。Sam’s Duet 查看代码，指出内部报表尚未包含处理状态。输出中同时展示自然语言意见和独立的 `changes_requested` 结果字段。外圈高亮匹配的规则。

### 旁白

Maya 把需求写成产品需求条目，也就是 story。Alex 的 Duet 开始实现，并提交供团队评审的代码变更请求，也就是 PR。GitHub 发出一个带有 PR 和提交版本的事件。独立运行的 Agent Loop 根据规则文件 policy，把评审交给负责这项工作的 Sam。外圈执行确定的规则，无需调用模型。Sam 的 Duet 才负责理解代码和检查需求。它发现，客户页面已经展示状态，但内部报表还没有对应字段。它提交具体意见，并给出明确的需要修改结论。Agent Loop 读取这个结构化结果，知道下一棒该回到作者那里。

### 转场

红色修改意见沿外圈回到 Alex，摄像机跟随同一 PR 的版本更新。

## 09 修复结果重新进入同一条流程

### 观众理解

一次结果能触发下一次工作。同一需求、PR 和提交版本把修改过程串在一起。

### 画面推进

约 35 秒。意见由配置好的 GitHub 集成写回 PR，Alex’s Duet 收到包含问题和来源的任务。它补充内部报表的 **Processing status** 列，追加提交。新版本再次进入 Sam 的评审，结论变为 `approved`。Agent Loop 将需求、版本和验收条件交给 LoopLab。屏幕上的 story 始终保留两项要求，避免只关注代码。

### 旁白

规则把意见写回 PR，并把修改任务交给 Alex 的 Duet。它拿到具体缺项和对应版本，补上报表字段，再追加提交。新版本进入同一套评审规则，Sam 的 Duet 检查后给出通过结论。接下来，Agent Loop 可以把本次变更交给 LoopLab，连同要验证的需求和条件一起送过去。每次交付都带着下一位执行者能直接使用的上下文。

### 转场

代码画面变成真实浏览器，要求逐条变成可执行的验收检查。

## 10 LoopLab 用浏览器运行给出证据

### 观众理解

测试编排与独立回放是两个阶段。验收结果来自固定流程的实际运行，并能再次成为调度事件。

### 画面推进

约 55 秒。Sam 的验收条件显示两项。客户页面正确显示 **In review**，内部导出报表同一申请的状态也为 **In review**。LoopLab Agent 调查页面，保存节点并编排流程。随后关闭调查视图，打开独立浏览器回放固定版本。逐项点亮页面断言和导出文件断言，记录截图与步骤。展示 `passed` 结果和报告链接，红色失败支路标明若有断言失败则携证据返回 Alex’s Duet，主故事沿通过支路继续。

### 旁白

Sam 给出了两条验收条件。客户应该看到申请正在审核，内部导出的同一条记录也应该包含这个状态。LoopLab 的 Agent 调查真实页面，把操作编排成可复用的节点和流程。随后，独立浏览器执行固定版本的流程，逐条检查页面和导出结果，留下步骤与截图。回放按确定的步骤执行。测试通过时，结果带着证据回到流程。若有检查失败，Agent Loop 可以把失败位置和证据交回 Alex 的 Duet，继续修复和复验。

### 转场

同一次验收拆成一份人能读的报告和一条机器能处理的事件，分别进入消息中心和外圈。

## 11 每个人知道自己的事推进到了哪里

### 观众理解

共享验收证据与各人的 Tracking 可以共同支持后续决定。一个技术结果可以服务不同职责。

### 画面推进

约 40 秒。验收报告进入 Message Center 和绑定主题，结构化结果进入 Agent Loop。Nora 的 Tracking 更新为「影响研究已转成经过验证的功能」，Maya 更新为「需求已验收，待安排发布」，Alex 更新为「改动已通过复验」，Sam 留下测试运行和证据。Maya 在自己的 Duet 中查看报告并决定发布时间。保留报告链接在各记录中一致，示意各方引用同一次运行。

### 旁白

验收报告回到共享主题，也能在消息中心里查到。Nora 知道，最初发现的变化已经推进成了经过验证的功能。Maya 看见需求的验收结果，继续安排发布。Alex 和 Sam 的 Tracking 则记录改动、复验和证据。每个人从自己的职责出发跟踪同一项工作，并引用同一份结果。人需要做决定时，Duet 能把进度、材料和剩余选择一起带到面前。

### 转场

从各自 Tracking 的共同证据拉远，重新看见整条路径和外圈。

## 12 成熟的交接成为下一条自动流程

### 观众理解

个人委托、共享信息、确定性规则和独立验收共同组成业务闭环。组织可以逐条扩展成熟的工作方式。

### 画面推进

约 40 秒。沿完整路径回顾五个交付物，资讯、报告、story、PR、验收证据。外圈标出 Agent Loop，圆内依次点亮 Message Center、各人的 Duet 和 LoopLab。最后将「新 PR 交给谁」「需要修改交回谁」两次稳定交接收拢成 policy。四位员工仍在画面中，旁边保留目标、优先级和发布时间等决定。

### 旁白

回看这条路径，消息中心让变化被发现，Duet 理解并完成每个人交出去的工作，Agent Loop 按规则交接，LoopLab 提供验收证据。团队可以先把一段真实工作做顺，再将反复发生的交接写成 policy，由负责人确定规则。人继续决定目标、优先级和承诺。随着更多岗位的交付可以互相接住，公司就能逐条建立自己的 AI Native 业务闭环。

### 收束

停留在完整路径和最后一份验收证据，让观众看清这条业务从何而来、交到了谁手里、以什么条件收尾。

## 制作说明

旁白时长为估计，最终随录音语速和画面停顿校准。先审阅内容、人物关系与交互路径，再锁定逐句时间轴。普通话配音音色尚未选定，可在内容确认后选择合适的合成声音。最终字幕以旁白原文生成。
