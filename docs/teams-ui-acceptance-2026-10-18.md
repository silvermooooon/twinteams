## Attachment acceptance contract

The following checks define the required behavior. Actual checked cases and remaining OS-input limitations are recorded below.

- Validate supported image format from actual bytes, reject malformed/decompression-abuse input, and reject mismatched claimed image MIME rather than trusting filename or browser MIME alone.
- Only the uploader and correct chat scope can attach an uncommitted upload. Download/original URLs re-check membership and history access; opaque IDs alone never grant access.
- Unsupported non-images remain downloadable message cards with an unsupported marker. Their contents and names do not enter prompts, summaries, routing, or SDK model context.
- A message containing only unsupported files must not schedule or execute an LLM call. Text plus unsupported files sends only the text; image-only and text-plus-image send actual SDK image blocks.
- Reusing a send key cannot create a duplicate message or bind different attachment IDs. Upload/send failure must preserve the user's draft and expose an understandable retry path.
- Reopening history and reconnecting must preserve authorized attachment metadata and original download access. Pending uploads must not appear in another owner's or chat's composer.
- Offline tests capture the SDK input and invocation count. A final live recognition check uses only the user-approved `gpt-6-luna` provider and a generated non-sensitive image. No credentials may appear in logs or screenshots.

## Interaction and layout checklist

Only states explicitly recorded in the results below have been checked; this checklist does not imply complete coverage.

- Menus: pointer hover/focus visibility; click outside; Escape; appropriate Arrow/Home/End behavior for menu/tab patterns; focus return; unclipped anchoring near viewport edges.
- Modals: initial focus, visible focus, Tab/Shift+Tab containment, Escape/backdrop close, focus return, busy close disabled, nested modal ordering.
- Drawers: keyboard close/back, focus return, independent scrolling, long title/path/event wrapping, tab selection and arrow-key behavior.
- Scrolling: chat-list/history/drawer/form independence; composer stays reachable when banners, typing, queues, approval card and reply preview coexist; load-earlier retains reading position.
- Width/height: desktop reference size; 1280px; 768px; 390px; short viewport. No inaccessible header action or zero-width composer. Long names and unbroken text must not force page overflow.
- Motion: sample actual computed CSS and visible start/end states. Check `prefers-reduced-motion: reduce` stops transitions/animations while status remains understandable.
- Truthful affordances: omit meeting/calendar/Copilot/call/GIF/cloud-file and other unconnected entry points, including disabled placeholders. Keep workspace upload in its existing workspace context. Existing local emoji insertion and loaded-message search may be presented with their real scope.
